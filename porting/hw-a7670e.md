# Модем SIMCOM A7670E-LASE ↔ OVMS3 v3.3.006 (LILYGO T-2CAN)

Задача (см. `porting/TEAM.md`): A7670E-LASE vs FASE, драйвер `simcom`, PPP/питание.
Только исследование/документация — код в этой работе не менялся.

**Итог в шести пунктах**

1. Апстрим-драйвер `simcom_7670.cpp` написан именно под этот модуль (имя `A7670E`,
   автодетект по `AT+CGMM`, MUX + `ATD*99#` + PPP) — он подходит, правок для запуска не требуется.
2. **LASE = без GNSS, FASE = с GNSS**; полосы у них одинаковые (их задаёт суффикс «E»:
   FDD B1/B3/B5/B7/B8/B20 + GSM 900/1800, TDD нет). Для OVMS GPS выключен по умолчанию — разница не критична.
3. Главные разрывы не в софте, а в железе: уровни 1.8 В UART/DTR (abs.max 2.1 В) против 3.3 В
   ESP32, отдельный источник питания 3.4–4.2 В / пик 2.8 А, отсутствие на плате T-2CAN как самого
   модема, так и транзистора PWRKEY.
4. `MODEM_GPIO_RST` (`t2can_can.h:30`) ≠ `MODEM_GPIO_RESET` (`ovms_peripherals.cpp:122`) —
   RESET (GPIO16) прошивкой не инициализируется и не используется.
5. Конфиг прошивки уже согласован с T-2CAN: консоль на USB-Serial/JTAG (UART0 свободен),
   UART1 = модем 115200 8N1 без flow control, MAX7317 выключен, маппинг `t2can_can.h`.
6. Единственная содержательная правка софта (с отдельного разрешения): `GetNetTypes()`
   возвращает `"auto 2G 3G 4G"`, а у A7670 3G нет — выбор 3G уводит `AT+CNMP=14` в бесконечный поиск сети.

### 1.2 Суффиксы маркировки SIMCom (правило наименования)

Суффикс состоит из двух частей: **suffix-1 = регион/диапазоны**, **suffix-2 = функции**.

| suffix-1 | Регион | LTE-FDD | LTE-TDD |
|---|---|---|---|
| **A7670C** | Китай | B1/B3/B5/B8 | B34/38/39/40/41 |
| **A7670E** | Европа/Россия и др. | **B1/B3/B5/B7/B8/B20** | **нет** |
| **A7670SA** | Южная Азия | B1/B2/B3/B4/B5/B7/B8/B28/B66 | нет |
| A7670G | глобальный | (по таблице SIMCom) | — |

Источник таблицы полос — **Table 1 «Module frequency bands»** официального Hardware Design V1.00
(сверено по layout-извлечению текста PDF, галочки = Wingdings): галочки по столбцу «A7670E» стоят
только на EGSM900, DCS1800 и FDD B1/B3/B5/B7/B8/B20; **TDD-строки у E пустые**. Это важнее
маркетинговых таблиц: LCSC и electrodragon приписывают E полный TDD B34…B41, официальный документ — нет.

Важно: **полосы определяются буквой «E», а не LASE/FASE** — здесь расхождений нет.

### 1.3 LASE vs FASE (функциональный суффикс)

| Признак | **A7670E-LASE** | **A7670E-FASE** |
|---|---|---|
| 4G LTE Cat-1 + GSM/GPRS | да | да |
| Приёмная антенна (diversity, 2 порта) | да | да |
| **GNSS (GPS)** | **нет** | **есть** |
| Полосы (суффикс «E») | идентично: FDD B1/B3/B5/B7/B8/B20 + GSM 900/1800 | идентично |
| Команды `AT+CGNSSPWR`, `AT+CGNSSINFO`, `AT+CGNSSMODE` | вернут `ERROR` | работают |
| Разъём антенны GNSS | отсутствует | есть (MAIN + DIV + GNSS) |
| Цена/наличие | дешевле, распространённее | дороже |
| Влияние на OVMS | GPS в OVMS выключен по умолчанию → **разницы в работе нет** | то же, пока GPS не включат |

Уверенность в утверждении «LASE = без GPS, FASE = с GPS»:

- **Основание**: таблица расшифровки суффиксов SIMCom (electrodragon, A7670-DAT):
  `LASE = 4G + GPRS, diversity antenna, NO GPS`, `FASE = 4G + GPRS + GNSS`
  (там же `LABE` — вариант без GPS). Явного даташита с такой таблицей на simcom.com найти не удалось
  (раздел отдаётся через JS, поисковики частично блокируются).
- **Косвенные подтверждения**: вариантная таблица LILYGO T-A76XX (GPS-версии заказываются отдельно),
  карточки LCSC (LASE — C5362211, FASE — C7435296), SEO-статьи маркетплейсов (низкая надёжность).
- **Что в репозитории проекта**: `PLAN.md` ставит целью **A7670E-LASE**, а `REPORT.md:6` и
  `gpio_maps/t2can_can.h:6,25` пишут **«A7670E-FASE»**. Это незакрытое противоречие — закрывается
  осмотром маркировки на корпусе модуля (§5, п.1).

**Вывод для интеграции**: драйверу LASE/FASE безразличны (маппинг по `AT+CGMM`, см. §2). Единственное
следствие LASE — GPS-ветка прошивки (`StartupNMEA`, опрос `AT+CGNSSINFO`) будет получать `ERROR`;
включается она только ключом `modem/enable.gps` (по умолчанию `no`, `ovms_cellular.cpp:1766`).

## 4. Сценарий инициализации AT/PPP (кратко, по шагам)

1. **PoweringOn** → `PowerCycle()` → `SimcomPowerCycle(-1, 70)` (`simcom_7670.cpp:117`):
   PWRKEY Low 70 мс (спец: Ton ≥ 50 мс) → пауза `TPwrOffOn=5000 мс` (спец: Toff-on ≥ 2 с) →
   Low 200 мс → High. Ожидание ответов до 30 тиков (`ovms_cellular.cpp:658`).
   *Power-off*: `SimcomPowerOff(2500)` (`simcom_powering.h:70`) ≥ спец Toff 2500 мс ✓.
2. **Identify** → `AT+CGMM` (`:928`) → `IdentifyModel()` (`:1402`) находит ключ `"A7670"` →
   включается `simcom7670`; таймаут 30 тиков, при неудаче → `PowerOffOn` (`:664`).
   Если в конфиге `modem/driver` = `auto` (дефолт, `:629`) — каждый `PoweringOn` сбрасывает на auto (`:650-654`).
3. **PoweredOn** → стартовый набор (`:942`) → `AT+CMUX=0` (`:948`) → `StartMux()` (`:1578`) →
   `GsmMux`: DLCI 0 CTRL / 1 NMEA / 2 DATA / 3 POLL / 4 CMD (`gsmmux.cpp:204-209`).
4. **NetWait** → `AT+CGATT=1` + `StatusPoller` (`simcom_7670.cpp:120-151`):
   `AT+CREG?;+CGREG?;+CEREG?;+CCLK?;+CSQ` → `AT+CPSI?` → `AT+COPS?`.
5. **NetStart** (драйверный override, `simcom_7670.cpp:155-181`), при `m_state1_ticker == 1`:
   - `AT+CGNSSPWR=?` (проба GPS, для LASE → ERROR);
   - на канале DATA: `AT+CGDCONT=1,"IP","<modem/apn>"` затем **`ATD*99#`**;
   - `m_state1_userdata = 1`; `++m_state1_ticker` — generic-ветка `ovms_cellular.cpp:995`
     (`+CGDATA="PPP",1`) не выполняется, потому что `AT+CGDATA=?` у A76XX возвращает пустой список L2P.
6. Модуль отвечает URC **`CONNECT `** → `m_state1_userdata = 2` (`ovms_cellular.cpp:1121-1125`) →
   `NetMode` → `StartPPP()` (`:1611`) → `GsmPPPOS::Initialise(mux, m_mux_channel_DATA)` (`gsmpppos.cpp:206`)
   → `pppapi_pppos_create` → LCP/IPCP/PAP → lwIP `pppos` netif → событие `network.up`.
7. **Отказы**: `ERROR` → `userdata=100` → `PowerOffOn` (`:1126-1130`, `:1004-1008`);
   `+PPPD: DISCONNECTED` → `userdata=99` → `NetLoss` (`:1131-1135`);
   нет валидного MUX-фрейма > 180 с → `StopPPP`/`StopMux`/power cycle (`:890-897`).
8. Штатная работа: PPP поверх MUX DLCI2, команды на DLCI4 (CMD), статус на DLCI3 (POLL).

## 5. Риски и открытые вопросы

1. **Есть ли вообще модем и какая у него маркировка.** Официальные страница/wiki/GitHub LILYGO T-2CAN
   модема не упоминают (в README — только ESP32-S3 + 2×CAN, MCP2515/MCP2518); на схеме
   `project/T-2Can_V1.0.pdf` нет ни слота SIM, ни транзистора PWRKEY, ни уровня на UART.
   В репозитории проекта противоречие: `PLAN.md` = **LASE**, `REPORT.md:6` и `t2can_can.h:6,25` = **FASE**.
   → снять маркировку с корпуса модуля.
2. **Уровни 1.8 В** (разрыв №4) — единственный пункт, который может физически повредить модуль при
   прямом подключении 3.3 В UART/DTR. Проверить мультиметром/осциллографом до подачи питания.
3. **Полярность PWRKEY** (разрыв №3): если инвертора нет, прошивка будет «включать» модем выключением.
   Проверить: GPIO15=1 → замерить уровень на PWRKEY.
4. **Питание 2.8 А / 300 мкФ** (разрыв №6) — просадки питания = «модем не включается / падает PPP».
5. **`ATD*99#` не формализован в мануале** (§2.2): в A76XX AT Manual V1.12 раздел `ATD` описан как
   голосовой набор, а `CGDATA=?` возвращает пустой список. Нужен smoke-тест на стенде:
   `ATD*99#` → `CONNECT`, затем `+PPPD: DISCONNECTED` при разрыве.
6. **Ревизия прошивки модуля ≠ ревизия мануала**: все подтверждения — по V1.12/V1.00; сверить
   фактические ответы `AT+CGMM`, `AT+CMUX=?`, `AT+CNMP=?`, `AT+CGDATA=?` на своём экземпляре.
7. **B7**: официальная Table 1 включает FDD B7 для A7670E, таблица LILYGO (B1/B3/B5/B8/B20) — нет.
   Для России (B7 у ряда операторов) это важно → уточнить по факту модуля/оператора.
8. **TDD в A7670E отсутствует** (Table 1) — вопреки LCSC/electrodragon; не закладываться на B38-B41.
9. **Правки кода, требующие отдельного разрешения техлида** (в рамках этой работы не делались):
   - `MODEM_GPIO_RST` → `MODEM_GPIO_RESET` (§3 №1);
   - `GetNetTypes()` → `"auto 2G 4G"` (§3 №7);
   - при желании — отключение GPS-ветки для LASE (п.8 §3: не обязательно).
10. **Не проверено на стенде**: полный цикл §4 (питание → идентификация → MUX → PPP → `network.up`
    → V2 на сервер), восстановление после обрыва сети, поведение при `ERROR`/`PowerOffOn`.
11. **Антенны** (разрыв №14): diversity требует двух антенн с изоляцией ~20 дБ; без антенн
    регистратор сети не выйдет — этот шаг логистический, не программный.
12. Слабое место источника по LASE/FASE: прямого даташита «LASE = без GNSS» нет (§1.3) —
    разделение подтверждено таблицей суффиксов SIMCom + косвенными данными; при расхождении
    доверять маркировке на корпусе и ответу `AT+CGNSSPWR=?`.
